# Voltix Dash animation presentation

60 original vector-based frames, derived from the existing editable Player, PatrolBot,
ElectricBarrier, MovingHazard and GoalPortal SVG geometry. No external artwork or packages.

## Controllers

- `Controllers/Player.controller`: base Locomotion state contains an exact-threshold
  1D blend tree (`Motion`: Idle=0, Run=1, JumpStart=2, Rise=3, Fall=4, Land=5).
  Dedicated presentation code selects a threshold from live physics and feedback events;
  changing motion restarts its clip without a crossfade. The override Action layer has
  Neutral, Attack and Hurt states. Two guarded Any State transitions give Hurt priority
  over an accepted Attack; both return to live locomotion. Action layer weight is zero
  when inactive. Bool parameters: `Attack`, `Hurt`.
- `Controllers/PatrolBot.controller`: Patrol loop, terminal Death state selected by
  `Dead`. The same controller is reused on the collider-free death visual prefab.
- `Controllers/ElectricBarrier.controller`, `MovingHazard.controller`,
  `GoalPortal.controller`: one looping sprite state each.

All clips animate **only SpriteRenderer.m_Sprite**, with centered full-rectangle frames
and consistent bounds within each character. No position, rotation, scale, color,
collider, physics, gameplay parameter or animation-event tracks. Animators use Normal
scaled-time updates, no root motion. Pause freezes both clips and visual event windows.

## Presentation scripts

`Assets/Scripts/Animation/PlayerAnimationController.cs` subscribes to existing feedback
Jumped/Landed, accepted combat AttackPerformed, health changes and respawn events. It
reads Rigidbody2D velocity, the matching ground check/mask and existing combat facing.
Attack and Hurt are visual overrides only; their short windows use clip duration, never
control attack cooldown, hit checks or health. Input Send Messages remains solely in
existing gameplay handlers; presentation event handlers use distinct names.

`EnemyAnimationController.cs` reads the new read-only PatrolEnemy.FacingDirection property.
On lethal disable it spawns `../Prefabs/PatrolBotDeathVisual.prefab` at the current visual
pose. Existing EnemyHealth still disables/destroys the gameplay object and awards score
immediately. The visual copy has no collider, movement, health or score component;
`EnemyDeathPresentation.cs` destroys it after its terminal clip finishes. Existing enemy
burst, shake and audio still run independently.

The existing Player/Visual child remains the feedback target. Sprite animation changes
poses while PlayerFeedback alone owns its additive squash/stretch transforms and
material-property flash. Existing camera shake, slash, jump/landing audio, damage audio
and death feedback are unchanged. No new materials or AudioSources.

## Editing / regeneration

Edit individual frame groups in the SVG sheets with a vector editor. They remain source
artwork even though Unity uses PNG sprite sheets, requiring no SVG importer package.
The compact generator `../Source/Animation/generate_animation_art.py` recreates both SVG
and antialiased PNG sheets from the original character/prop SVG designs. Run it with
Python 3 and Pillow already available on the authoring machine. `manifest.json` records
frame dimensions, pixels per unit, FPS and looping. Manual SVG edits are independent
and will be overwritten if regenerated; retain them before rerunning the generator.

Player cells are 256x128 at 128 PPU with extra transparent horizontal room for arm poses;
the original body geometry stays centered. PatrolBot/barrier/mover cells are 128x128
at 128 PPU. Portal cells are 192x320 at 80 PPU, preserving its 2.4x4 world bounds.
Mipmaps and autogenerated physics outlines are disabled. Largest sheet is 2048 pixels
wide; the sheets total about 7 MB uncompressed RGBA texture storage, without mipmaps.
